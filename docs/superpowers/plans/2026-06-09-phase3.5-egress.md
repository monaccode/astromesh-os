# Fase 3.5 — Egress Governance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply deny-by-default network egress governance to `astromeshd` via systemd `IPAddressDeny=`/`IPAddressAllow=` (eBPF cgroup/skb under the hood), fail-closed (ADR-4), and prove it with a self-contained boot gate.

**Architecture:** A `40-egress.conf` drop-in puts `IPAddressDeny=any` + a minimal allowlist on `astromeshd.service` and wires `Requires=astromesh-egress-check.service`. The self-check carries the SAME IP filter, runs `Before=astromeshd`, and proves the policy is active (POLICY-ACTIVE), that an allowed destination is reachable (POSITIVE-ALLOW, loopback), and that a denied destination is refused (POSITIVE-BLOCK, EPERM to a TEST-NET IP). The gate boots the image, asserts the markers + `/v1/health` 200. Additive to AppArmor (3.2), sandbox (3.4), unseal (3.3) — and backward-compatible with every health-via-hostfwd gate because the allowlist includes the QEMU user-net subnet.

**Tech Stack:** systemd resource-control (`IPAddressDeny`/`IPAddressAllow`, cgroup-BPF), Debian trixie / kernel 6.12 (CONFIG_CGROUP_BPF), mkosi, QEMU, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-06-09-phase3.5-egress-design.md`

**Patterns to mirror:** `phase3/sandbox/30-sandbox.conf` + `astromesh-sandbox-check.{sh,service}` (drop-in + fail-closed self-check carrying the same directives), `tests/boot/sandbox-and-assert.sh` (1-boot gate skeleton), the Fase 3.4 block in `mkosi.postinst.chroot`, `.github/workflows/phase3-sandbox.yml`.

**Branch:** `feat/phase3.5-egress` (created; spec committed there).

## Key design facts (verified during planning)

- **Stub mode (CI + local gate):** `astromeshd` reaches the provider at `http://127.0.0.1:8081/v1` (the phase0 stub, `--host 127.0.0.1`). Loopback → covered by `IPAddressAllow=localhost`. No DNS/external egress needed for the gates.
- **Health ingress:** the image brings up the NIC via DHCP (`10.0.2.15`); the host reaches `/v1/health` through QEMU `hostfwd`, whose connections enter the guest **from the gateway `10.0.2.2`**. `IPAddressDeny=any` filters **ingress as well as egress**, so the allowlist MUST include the QEMU user-net subnet `10.0.2.0/24` or every health-via-hostfwd gate (sandbox/confine/tpm/secureboot/rollback/phase0) breaks. `10.0.2.0/24` is RFC1918 and inert in real clouds; prod replaces it with the real probe/LB CIDR + provider CIDRs.
- **errno semantics — CORRECTED after empirical validation (see commit `fix(phase3.5): POSITIVE-BLOCK …`):** the original assumption below was WRONG. A controlled `systemd-run -p IPAddressDeny=any` experiment (kernel 6.x) showed a denied connect **TIMES OUT** (silent cgroup-BPF drop, `socket.timeout`, errno None), it does **not** return `EPERM`. An allowed-but-closed loopback port returns `ECONNREFUSED` fast. The real test: POSITIVE-ALLOW expects `ECONNREFUSED` (not TIMEOUT/EPERM); POSITIVE-BLOCK accepts `TIMEOUT` *or* `EPERM` as blocked, and treats `CONNECTED`/`ECONNREFUSED` as an egress **leak** (FAIL).
  - ~~Original (incorrect): a cgroup-BPF egress drop makes `connect()` fail immediately with `EPERM`, no internet needed.~~
- **Block target — CORRECTED:** `1.1.1.1:443` (routable). The original `192.0.2.1` (TEST-NET) was non-routable, so it timed out **with or without** the filter — vacuous. `1.1.1.1` connects fast when allowed and times out when the filter drops it, so the timeout is provably the filter (non-vacuous). Requires the guest have outbound internet via slirp NAT (present in KVM/WSL/CI). Tasks 2's embedded script below reflects the ORIGINAL design; the committed script is the corrected version.

```ini
[Unit]
# Fase 3.5 egress governance: deny-by-default network egress (and ingress) for astromeshd via
# systemd IPAddress filtering (cgroup-BPF), complementing the Fase 3.2 AppArmor (paths) and Fase 3.4
# sandbox (syscalls/namespaces). ADR-4: the agent must not run without governed egress. Fail-closed
# wiring: astromeshd Requires= the egress self-check, which carries the SAME IP filter and runs
# FIRST. If the kernel/systemd cannot install the filter, the check fails to start -> Requires=
# fails -> astromeshd does not start. The check also runs a positive-allow + positive-block, gating CI.
Requires=astromesh-egress-check.service
After=astromesh-egress-check.service

[Service]
# Deny-by-default: drop all IPv4/IPv6 traffic of this service's cgroup except the allowlist below.
IPAddressDeny=any
# Loopback: the stub provider (127.0.0.1:8081 in stub mode) and any intra-host IPC + /v1/health.
IPAddressAllow=localhost
# QEMU user-net subnet: lets the harness reach /v1/health via hostfwd (connections enter the guest
# from the gateway 10.0.2.2). RFC1918, inert in real clouds. PRODUCTION must replace this with the
# real health-probe/LB CIDR and add the provider CIDRs (see phase3/egress/README.md).
IPAddressAllow=10.0.2.0/24
```

`phase3/egress/README.md`:

```markdown
# Egress governance (Fase 3.5)

`40-egress.conf` puts deny-by-default network filtering on `astromeshd` via systemd
`IPAddressDeny=any` + an `IPAddressAllow=` allowlist. systemd compiles/installs cgroup-BPF programs
to enforce it — real egress-eBPF without custom Rust. Fail-closed (ADR-4): if the filter can't be
applied, `astromesh-egress-check.service` fails and `astromeshd` (which `Requires=` it) won't start.

## Shipped default allowlist

- `localhost` — loopback (stub provider on 127.0.0.1:8081, `/v1/health`, local IPC).
- `10.0.2.0/24` — the QEMU user-net subnet, so the boot gates can reach `/v1/health` via hostfwd.
  **This is for the test harness.** It is RFC1918 and does nothing in a real cloud.

The default ships **no provider CIDRs**, so a real deployment's agent can serve health but cannot
reach the provider until you add them. That is fail-closed by design: preferable to open egress.

## Production

Edit `40-egress.conf` and:

1. Replace `10.0.2.0/24` with the real health-probe / load-balancer source CIDR (or drop it if health
   is scraped over loopback only).
2. Add the provider's egress CIDRs and the DNS resolver, e.g.:

       IPAddressAllow=<dns-resolver-ip>/32
       IPAddressAllow=<provider-cidr-1>
       IPAddressAllow=<provider-cidr-2>

Anthropic does not publish stable CIDRs; source them from your egress proxy / NAT range, or front the
provider with a fixed-IP egress proxy and allow only that. A per-hostname egress proxy and a systemd
generator that reads `/etc/astromesh/egress-allow.conf` are documented fast-follows, not in this MVP.
```

- [ ] **Step 1: Write the self-check script**

`phase3/egress/astromesh-egress-check.sh`:

```bash
#!/usr/bin/env bash
# Fase 3.5 egress self-check. Runs in-guest BEFORE astromeshd (which Requires= this unit), under the
# SAME IP filter (IPAddressDeny=any + the same IPAddressAllow lines). Asserts:
#   (1) POLICY-ACTIVE: astromeshd is configured with a non-empty IPAddressDeny (egress governed).
#   (2) POSITIVE-ALLOW: an allowlisted destination (loopback) is reachable through the filter — a
#       connect to 127.0.0.1:9 fails with ECONNREFUSED (port closed), NOT EPERM. EPERM here would
#       mean the filter wrongly blocks loopback (fail-open against the runtime's own health/stub).
#   (3) POSITIVE-BLOCK: a non-allowlisted destination is refused — a connect to 192.0.2.1:80
#       (TEST-NET-1, RFC5737, outside 10.0.2.0/24) fails with EPERM/EACCES. systemd's cgroup-BPF
#       drop returns EPERM locally, so this is deterministic and needs no internet.
# Logs [egress] markers to console for the gate harness. Fail-closed: non-zero exit on any failure,
# and because astromeshd Requires= this unit, a failure here prevents astromeshd from starting.
set -uo pipefail
log() { echo "[egress] $*"; }
fail=0

# probe HOST PORT -> prints CONNECTED or the errno code name (e.g. EPERM, ECONNREFUSED, ETIMEDOUT).
probe() {
    /usr/bin/python3 - "$1" "$2" <<'PY'
import socket, sys, errno
host, port = sys.argv[1], int(sys.argv[2])
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(3)
try:
    s.connect((host, port))
    print("CONNECTED")
except OSError as e:
    print(errno.errorcode.get(e.errno, "E%d" % (e.errno or 0)))
finally:
    s.close()
PY
}

# 1. POLICY-ACTIVE: astromeshd carries a non-empty IPAddressDeny.
deny=$(systemctl show astromeshd.service -p IPAddressDeny --value 2>/dev/null || echo "")
if [ -n "${deny}" ]; then
    log "POLICY-ACTIVE OK (astromeshd IPAddressDeny=${deny})"
else
    log "FAIL: astromeshd has no IPAddressDeny — egress not governed"
    fail=1
fi

# 2. POSITIVE-ALLOW: loopback must be permitted (errno must NOT be EPERM/EACCES).
allow=$(probe 127.0.0.1 9)
log "loopback 127.0.0.1:9 -> ${allow}"
case "${allow}" in
    EPERM|EACCES) log "FAIL: loopback blocked by the filter (${allow}) — allowlist not effective"; fail=1 ;;
    *)            log "POSITIVE-ALLOW OK (loopback permitted; ${allow})" ;;
esac

# 3. POSITIVE-BLOCK: a non-allowlisted external IP must be denied (errno EPERM/EACCES).
block=$(probe 192.0.2.1 80)
log "external 192.0.2.1:80 -> ${block}"
case "${block}" in
    EPERM|EACCES) log "POSITIVE-BLOCK OK (out-of-allowlist egress denied by the filter)" ;;
    CONNECTED|ECONNREFUSED) log "FAIL: external egress to 192.0.2.1 was NOT blocked (${block}) — deny-by-default not enforcing"; fail=1 ;;
    *)            log "FAIL: external connect gave ${block}, expected EPERM (filter denial) — cannot confirm enforcement"; fail=1 ;;
esac

if [ "${fail}" -ne 0 ]; then log "EGRESS FAILED"; exit 1; fi
log "EGRESS GATE OK"
```

`phase3/egress/astromesh-egress-check.service`:

```ini
[Unit]
Description=Astromesh OS Fase 3.5 egress self-check (deny-by-default IP filter, fail-closed)
# Runs BEFORE astromeshd, which Requires= this unit (see 40-egress.conf). This unit carries the SAME
# IP filter as astromeshd, so: (1) if the filter cannot be applied, THIS unit fails to start ->
# astromeshd's Requires= fails -> astromeshd does not start (fail-closed); (2) its own connect
# probes exercise the real allow/deny policy.

[Service]
Type=oneshot
ExecStart=/usr/lib/astromesh-os/astromesh-egress-check.sh
StandardOutput=journal+console
StandardError=journal+console
RemainAfterExit=yes
# Carry the SAME IP filter as astromeshd (phase3/egress/40-egress.conf) — keep in sync. The check
# runs under these, so its loopback (allow) and 192.0.2.1 (block) probes exercise the real policy.
IPAddressDeny=any
IPAddressAllow=localhost
IPAddressAllow=10.0.2.0/24

[Install]
WantedBy=multi-user.target
```

### Task 4: The egress gate

**Files:**
- Create: `tests/boot/egress-and-assert.sh`

- [ ] **Step 1: Write the gate** (mirror of `tests/boot/sandbox-and-assert.sh`)

`tests/boot/egress-and-assert.sh`:

```bash
#!/usr/bin/env bash
# Fase 3.5 gate: boot the image, assert astromeshd is functional UNDER the egress filter
# (/v1/health 200 via hostfwd — proves the allowlist did not break ingress/health or the loopback
# stub), then assert the in-guest self-check passed ([egress] EGRESS GATE OK on the console:
# POLICY-ACTIVE + POSITIVE-ALLOW + POSITIVE-BLOCK).
# Usage: egress-and-assert.sh <disk-image>
set -euo pipefail

IMAGE="${1:?usage: egress-and-assert.sh <disk-image>}"
PORT=8000
qemu-img resize "${IMAGE}" +3G >/dev/null

if [ -w /dev/kvm ]; then ACCEL="-enable-kvm"; SMP=2; else ACCEL="-accel tcg,thread=multi"; SMP=4; fi

OVMF_CODE=""
for c in /usr/share/OVMF/OVMF_CODE_4M.fd /usr/share/OVMF/OVMF_CODE.fd /usr/share/ovmf/OVMF.fd; do
    [ -f "$c" ] && { OVMF_CODE="$c"; break; }
done
OVMF_VARS_SRC=""
for v in /usr/share/OVMF/OVMF_VARS_4M.fd /usr/share/OVMF/OVMF_VARS.fd; do
    [ -f "$v" ] && { OVMF_VARS_SRC="$v"; break; }
done
[ -n "${OVMF_CODE}" ] && [ -n "${OVMF_VARS_SRC}" ] || { echo "[egress] FAIL: OVMF not found"; exit 1; }
cp "${OVMF_VARS_SRC}" ovmf_vars_egress.fd

echo "[egress] starting QEMU"
qemu-system-x86_64 \
    ${ACCEL} -machine q35 -m 2048 -smp ${SMP} -nographic \
    -drive if=pflash,format=raw,unit=0,readonly=on,file="${OVMF_CODE}" \
    -drive if=pflash,format=raw,unit=1,file=ovmf_vars_egress.fd \
    -drive file="${IMAGE}",format=qcow2,if=virtio \
    -nic user,model=virtio-net-pci,hostfwd=tcp::${PORT}-:${PORT} \
    > egress-console.log 2>&1 &
QPID=$!
trap 'kill ${QPID} 2>/dev/null || true' EXIT

echo "[egress] waiting for /v1/health (timeout 240s) — proves the allowlist didn't break health/ingress"
deadline=$(( $(date +%s) + 240 ))
until curl -fsS "http://localhost:${PORT}/v1/health" >/dev/null 2>&1; do
    if [ "$(date +%s)" -ge "${deadline}" ]; then
        echo "[egress] FAIL: /v1/health never came up under the egress filter"; tail -n 120 egress-console.log; exit 1
    fi
    sleep 3
done
echo "[egress] PASS: /v1/health 200 under the egress filter"

echo "[egress] asserting in-guest egress self-check marker"
deadline=$(( $(date +%s) + 60 ))
until grep -aq 'egress\] EGRESS GATE OK' egress-console.log; do
    if grep -aq 'egress\] EGRESS FAILED' egress-console.log; then
        echo "[egress] FAIL: self-check reported EGRESS FAILED"
        grep -aE 'egress\]' egress-console.log | tail -20; exit 1
    fi
    if [ "$(date +%s)" -ge "${deadline}" ]; then
        echo "[egress] FAIL: egress self-check marker not seen"
        grep -aE 'egress\]' egress-console.log | tail -20; exit 1
    fi
    sleep 3
done
echo "[egress] PASS: egress self-check (policy-active + positive-allow + positive-block)"
echo "[egress] EGRESS GATE PASSED"
```

```yaml
name: phase3-egress

on:
  push:
    branches: [feat/phase3.5-egress]
  workflow_dispatch:

jobs:
  build-deb:
    runs-on: ubuntu-24.04
    container: debian:trixie
    defaults:
      run:
        shell: bash
    steps:
      - uses: actions/checkout@v4
      - id: pin
        run: |
          . runtime.pin
          echo "ref=${ASTROMESH_REF}" >> "$GITHUB_OUTPUT"
      - uses: actions/checkout@v4
        with:
          repository: monaccode/astromesh
          ref: ${{ steps.pin.outputs.ref }}
          path: _runtime
      - name: Install build deps
        run: |
          apt-get update
          apt-get install -y python3 python3-venv python3-pip git curl ca-certificates build-essential
      - name: Install nfpm
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          url=$(curl -sfL -H "Authorization: Bearer ${GH_TOKEN}" \
              https://api.github.com/repos/goreleaser/nfpm/releases/latest \
            | python3 -c "import sys,json; a=json.load(sys.stdin)['assets']; print(next(x['browser_download_url'] for x in a if x['name'].endswith('_amd64.deb')))")
          curl -sfL "$url" -o nfpm.deb
          apt-get install -y ./nfpm.deb
      - name: Build .deb
        working-directory: _runtime/astromesh-node
        run: bash packaging/build-deb.sh
      - run: mkdir -p dist && cp _runtime/astromesh-node/dist/astromesh-node_*_amd64.deb dist/

          name: astromesh-deb

    needs: build-deb
    runs-on: ubuntu-24.04
    container:
      image: debian:trixie
      options: --privileged
    defaults:
      run:
        shell: bash
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: astromesh-deb
          path: dist
      - name: Install mkosi + image tools
        run: |
          apt-get update

          PHASE0_MODE: stub

          name: phase3-egress-image

          path: image
      - name: Install QEMU + OVMF
        run: sudo apt-get update && sudo apt-get install -y qemu-system-x86 qemu-utils ovmf curl
      - name: Enable KVM access
        run: sudo chmod 666 /dev/kvm 2>/dev/null || echo "no kvm; TCG fallback"

        run: qemu-img convert -O qcow2 image/v1.raw egress.qcow2
```
