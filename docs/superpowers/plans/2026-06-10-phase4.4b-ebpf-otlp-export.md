# Fase 4.4b — Export OTel del mapa de egress por-flujo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A privileged (root) exporter reads the 4.4 eBPF `flows` map and emits per-flow egress bytes/packets as OTLP metrics to the 4.3 collector, proven by a 1-VM gate that runs an agent and finds the stub-call metric in the collector's debug dump.

**Architecture:** A root oneshot (fired by a 10s timer) runs `/opt/astromesh/venv/bin/python3` on `egress-otlp-export.py`, which guards on the runtime flags, dumps the BPF map via `bpftool`, and pushes `astromesh.egress.{bytes,packets}` ObservableGauges (attributes `daddr`/`dport`/`proto`) over OTLP/gRPC to `127.0.0.1:4317`. The 4.3 ocb collector gets a new `metrics` pipeline (no rebuild — its otlp/batch/debug components already handle metrics). No runtime change (astromeshd is non-root and can't touch the map; the exporter is a separate root unit reusing the venv's OTel SDK).

**Tech Stack:** OpenTelemetry SDK metrics (`MeterProvider` + `OTLPMetricExporter`, already in the deb venv via 4.3's `observability` extra), bpftool, the 4.4 eBPF map, the 4.3 otelcol sidecar, systemd timer, QEMU/swtpm, the 4.1 machine-config.

**Spec:** `docs/superpowers/specs/2026-06-10-phase4.4b-ebpf-otlp-export-design.md`

**Single repo:** `astromesh-os` (no node-source change — the exporter is OS-side, reusing the venv as root).

## Discovery facts (verified during planning)

- **astromeshd is non-root** (`User=astromesh`, `NoNewPrivileges=yes`); Debian `unprivileged_bpf_disabled` → it can't read the BPF map. The exporter MUST be a separate **root** unit. It reuses the venv's python (which has the OTel SDK), but runs as root (not under astromeshd's confinement).
- **Venv has metrics OTLP:** `opentelemetry.sdk.metrics.MeterProvider`, `…export.PeriodicExportingMetricReader`, `…exporter.otlp.proto.grpc.metric_exporter.OTLPMetricExporter`, `opentelemetry.metrics.Observation`, `meter.create_observable_gauge` — all import-verified against the deb venv. pyyaml is present (node dep) for the guard.
- **Collector already supports metrics:** the 4.3 ocb build (`phase4/otel/builder-config.yaml`) has otlpreceiver + batchprocessor + debugexporter, all of which handle metrics. Only `phase4/otel/otelcol.yaml` needs a `metrics` pipeline added (no binary rebuild).
- **No feedback loop:** the exporter runs in its own unit (own cgroup), so its OTLP traffic to `:4317` is NOT counted by the eBPF program (which is attached to astromeshd's cgroup).
- **Map dump parse:** reuse the `bpftool -j map dump` → key/value hex-list parse from 4.4's `egress-acct-dump.sh` (key `daddr(4) dport(2,!H) proto(1)`, value `bytes(8,<Q) packets(8,<Q)`).
- **Both flags drive the gate:** the gate's machine-config sets `ebpf_egress: true` + `otel: true` (both already supported by 4.4/4.3). The exporter guards on `spec.ebpf.egress.enabled` AND `spec.observability.otlp.enabled`.
- **Patterns to mirror:** `phase4/ebpf/egress-acct-dump.{sh}` + `.timer`/`.service` (4.4), `phase4/otel/*` (4.3), `tests/boot/otel-export-and-assert.sh` + `ebpf-egress-and-assert.sh`.

### Task 1: The exporter script + host validation

- [ ] **Step 1: Write the exporter** — `phase4/ebpf/egress-otlp-export.py`:

```python
#!/usr/bin/env python3
# Fase 4.4b: read the eBPF per-flow egress map and push it as OTLP metrics to the local collector.
# Runs as ROOT (astromeshd is non-root and cannot read BPF maps), reusing the venv's OpenTelemetry SDK.
# Guarded: no-op unless the active runtime.yaml has BOTH ebpf egress accounting AND otlp export enabled.
import json, socket, struct, subprocess, sys

RT = "/var/lib/astromesh/runtime.yaml"
MAP = "/sys/fs/bpf/astromesh/flows"
ENDPOINT = "http://127.0.0.1:4317"


def enabled() -> bool:
    try:
        import yaml
        d = yaml.safe_load(open(RT)) or {}
        spec = d.get("spec", {})
        ebpf = spec.get("ebpf", {}).get("egress", {}).get("enabled", False)
        otlp = spec.get("observability", {}).get("otlp", {}).get("enabled", False)
        return bool(ebpf and otlp)
    except Exception:
        return False


def read_flows():
    try:
        out = subprocess.run(
            ["bpftool", "-j", "map", "dump", "pinned", MAP],
            capture_output=True, text=True, timeout=5,
        ).stdout
        data = json.loads(out) if out.strip() else []
    except Exception:
        return []
    flows = []
    for e in data:
        k = e.get("key"); v = e.get("value")
        if not isinstance(k, list) or not isinstance(v, list):
            continue
        kb = bytes(int(x, 16) for x in k)
        vb = bytes(int(x, 16) for x in v)
        if len(kb) < 7 or len(vb) < 16:
            continue
        daddr = socket.inet_ntoa(kb[0:4])
        dport = struct.unpack("!H", kb[4:6])[0]
        proto = kb[6]
        nbytes, npkts = struct.unpack("<QQ", vb[0:16])
        flows.append((daddr, dport, proto, nbytes, npkts))
    return flows


def main():
    if not enabled():
        return
    from opentelemetry.metrics import Observation
    from opentelemetry.sdk.metrics import MeterProvider
    from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader
    from opentelemetry.exporter.otlp.proto.grpc.metric_exporter import OTLPMetricExporter
    from opentelemetry.sdk.resources import Resource

    flows = read_flows()

    def attrs(d, dp, pr):
        return {"daddr": d, "dport": dp, "proto": pr}

    def cb_bytes(options):
        return [Observation(b, attrs(d, dp, pr)) for (d, dp, pr, b, p) in flows]

    def cb_pkts(options):
        return [Observation(p, attrs(d, dp, pr)) for (d, dp, pr, b, p) in flows]

    exporter = OTLPMetricExporter(endpoint=ENDPOINT)
    # Long interval — we drive a single collection+export via force_flush, then exit (oneshot).
    reader = PeriodicExportingMetricReader(exporter, export_interval_millis=3_600_000)
    provider = MeterProvider(
        resource=Resource.create({"service.name": "astromesh-ebpf"}),
        metric_readers=[reader],
    )
    meter = provider.get_meter("astromesh.ebpf")
    meter.create_observable_gauge("astromesh.egress.bytes", callbacks=[cb_bytes], unit="By")
    meter.create_observable_gauge("astromesh.egress.packets", callbacks=[cb_pkts], unit="1")
    provider.force_flush(timeout_millis=8000)
    provider.shutdown()
    print(f"[ebpf] OTLP-EXPORTED {len(flows)} flow(s) -> {ENDPOINT}")


if __name__ == "__main__":
    main()
```

        -H 'Content-Type: application/json' -d '{"query":"ebpf otlp ping","session_id":"ebpf-otlp"}' >/dev/null 2>&1 || true
    sleep 1
done

# The exporter timer (every 10s) pushes the flow map as OTLP metrics; the collector debug-dumps them.
echo "[ebpf] asserting the egress metric reached the collector (astromesh.egress.bytes, dport 8081)"
deadline=$(( $(date +%s) + 120 ))
until grep -aqE 'astromesh\.egress\.bytes' "${CON}" && grep -aqE 'dport: Int\(8081\)|dport: 8081' "${CON}"; do
    if [ "$(date +%s)" -ge "${deadline}" ]; then
        echo "[ebpf] FAIL: egress metric not seen in the collector dump"
        grep -aE 'astromesh.egress|Metric #|dport|OTLP-EXPORTED|ebpf\]' "${CON}" | tail -n 40; exit 1
    fi
    sleep 3
done
echo "[ebpf] EBPF-OTLP-EXPORTED OK (astromesh.egress.bytes for the stub flow reached the collector)"
echo "[ebpf] EBPF OTLP GATE PASSED"
