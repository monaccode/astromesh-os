# Fase 3.4 — E-MVP Sandbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Confine `astromeshd` at the syscall + namespace + privilege level via a systemd drop-in (complementing the AppArmor path-confinement of Fase 3.2), with a fail-closed self-check, proven by a boot gate (KVM local + CI).

**Architecture:** A `astromeshd.service.d/30-sandbox.conf` drop-in adds `SystemCallFilter=@system-service` + namespace/privilege restrictions. Fail-closed is intrinsic: systemd refuses to start `astromeshd` if the sandbox cannot be applied. A oneshot `astromesh-sandbox-check.service` (After=astromeshd, carrying the same hardening) verifies the daemon's `MainPID` is seccomp-filtered + no-new-privs and runs a POSITIVE-BLOCK (a `unshare` that must be denied), emitting `[sandbox]` console markers. A single-boot gate asserts the markers + `astromeshd` health 200.

**Tech Stack:** systemd unit hardening (seccomp `SystemCallFilter`, `RestrictNamespaces`, etc.), bash self-check, QEMU/OVMF boot gate, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-06-09-phase3.4-sandbox-design.md`

**Patterns to mirror (read these first):** `phase3/apparmor/confine-check.sh`, `phase3/apparmor/confine-check.service`, `phase3/apparmor/20-apparmor.conf`, `tests/boot/confine-and-assert.sh`, `.github/workflows/phase3-confine.yml`, and the Fase 3.2/3.3 blocks in `mkosi.postinst.chroot`.

**Branch:** `feat/phase3.4-sandbox` (already created; spec already committed there).

### Task 1: Sandbox hardening drop-in

**Files:**
- Create: `phase3/sandbox/30-sandbox.conf`

- [ ] **Step 1: Write the drop-in**

`phase3/sandbox/30-sandbox.conf`:

```ini
[Unit]
# Fase 3.4 E-MVP sandbox: syscall + namespace + privilege confinement for astromeshd,
# complementing the Fase 3.2 AppArmor path-confinement. Fail-closed is INTRINSIC: if systemd
# cannot apply these sandbox directives, it fails to start astromeshd (the agent does not run
# without the sandbox — ADR-4). The astromesh-sandbox-check.service independently verifies this
# at boot and gates CI.

[Service]
# Privilege floor — no setuid/fscaps escalation; required for an unprivileged seccomp filter.
NoNewPrivileges=yes
# Curated allow-list for daemons (rarely breaks Python). Everything else is filtered.
SystemCallFilter=@system-service
# A filtered syscall returns EPERM instead of killing the process with SIGSYS, so the
# black-box runtime degrades rather than crash-loops if it touches something unforeseen.
SystemCallErrorNumber=EPERM
# Block non-native ABIs (no evading the filter via x32/compat).
SystemCallArchitectures=native
# Deny creating new namespaces (no self-containerization / userns escape attempts).
RestrictNamespaces=yes
# Only the socket families the runtime needs: provider + health (inet/inet6), local + DNS (unix).
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictRealtime=yes
RestrictSUIDSGID=yes
LockPersonality=yes
ProtectKernelModules=yes
ProtectKernelTunables=yes
ProtectKernelLogs=yes
ProtectClock=yes
ProtectHostname=yes
ProtectControlGroups=yes
PrivateTmp=yes
```

> Rationale and what is intentionally omitted (do not add): `MemoryDenyWriteExecute` is omitted
> (high risk of breaking Python C extensions; deferred per spec §1). `ProtectSystem=strict`/
> aggressive `ProtectHome` are omitted — the root is already verity read-only (Fase 2) and AppArmor
> 3.2 restricts paths; over-restriction could collide with the 3.3 unseal to `/run` or the venv in
> `/opt`. `EnvironmentFile=-/run/astromesh/env` (3.3) is read by systemd BEFORE applying the
> sandbox to the payload, so the unseal is unaffected.

# exercises the real sandbox profile. Keep in sync with phase3/sandbox/30-sandbox.conf.

SystemCallErrorNumber=EPERM
SystemCallArchitectures=native
RestrictNamespaces=yes

RestrictSUIDSGID=yes

[Install]

- [ ] **Step 2: Write the self-check script**

`phase3/sandbox/astromesh-sandbox-check.sh`:

```bash
#!/usr/bin/env bash
# Fase 3.4 sandbox self-check (runs in-guest, after astromeshd is up). Asserts:
#   (1) astromeshd's MainPID is running under a loaded seccomp filter (Seccomp: 2),
#   (2) astromeshd has NoNewPrivs set (NoNewPrivs: 1),
#   (3) POSITIVE-BLOCK: creating a new namespace is actually denied under the sandbox
#       (this unit carries the same hardening, so an unshare here proves the profile blocks).
# Logs [sandbox] markers to console for the gate harness. Fail-closed: non-zero exit on any fail.
set -uo pipefail
log() { echo "[sandbox] $*"; }
fail=0

# 1+2. Inspect astromeshd's MainPID confinement via /proc/<pid>/status.
pid=$(systemctl show -p MainPID --value astromeshd 2>/dev/null || echo 0)
seccomp=$(awk '/^Seccomp:/{print $2}' "/proc/${pid}/status" 2>/dev/null || echo "")
nnp=$(awk '/^NoNewPrivs:/{print $2}' "/proc/${pid}/status" 2>/dev/null || echo "")
log "astromeshd MainPID=${pid} Seccomp=${seccomp:-?} NoNewPrivs=${nnp:-?}"
# Seccomp: 2 == SECCOMP_MODE_FILTER (a filter is loaded).
if [ "${seccomp}" = "2" ]; then log "SECCOMP OK"; else log "FAIL: astromeshd not seccomp-filtered (Seccomp=${seccomp:-none})"; fail=1; fi
if [ "${nnp}" = "1" ]; then log "NO-NEW-PRIVS OK"; else log "FAIL: astromeshd without NoNewPrivs (NoNewPrivs=${nnp:-none})"; fail=1; fi

# 3. POSITIVE-BLOCK: under RestrictNamespaces (this unit carries it), creating a new user
#    namespace must be denied. unshare(2) is blocked by the seccomp namespace restriction and
#    surfaces as EPERM ("Operation not permitted"). A success here means the sandbox is NOT
#    enforcing namespace restriction.
err=$(unshare --user --map-root-user true 2>&1)
rc=$?
if [ "${rc}" -eq 0 ]; then
    log "FAIL: unshare(new userns) SUCCEEDED under the sandbox (RestrictNamespaces not enforcing)"
    fail=1
elif printf '%s' "${err}" | grep -qiE 'Operation not permitted|EPERM|permission denied'; then
    log "POSITIVE-BLOCK OK (new-namespace creation denied by the sandbox)"
else
    log "FAIL: unshare failed but not via permission-denied. stderr: ${err}"
    fail=1
fi

if [ "${fail}" -ne 0 ]; then log "SANDBOX FAILED"; exit 1; fi
log "SANDBOX GATE OK"
```

### Task 4: Boot gate (sandbox-and-assert.sh)

**Files:**
- Create: `tests/boot/sandbox-and-assert.sh`

- [ ] **Step 1: Write the gate** (mirror of `tests/boot/confine-and-assert.sh`)

`tests/boot/sandbox-and-assert.sh`:

```bash
#!/usr/bin/env bash
# Fase 3.4 gate: boot the image, assert astromeshd is functional UNDER the sandbox
# (/v1/health 200), then assert the in-guest self-check passed ([sandbox] SANDBOX GATE OK on
# the console: seccomp-filtered + no-new-privs + namespace POSITIVE-BLOCK).
# Usage: sandbox-and-assert.sh <disk-image>
set -euo pipefail

IMAGE="${1:?usage: sandbox-and-assert.sh <disk-image>}"
PORT=8000
qemu-img resize "${IMAGE}" +3G >/dev/null

if [ -w /dev/kvm ]; then ACCEL="-enable-kvm"; SMP=2; else ACCEL="-accel tcg,thread=multi"; SMP=4; fi

OVMF_CODE=""
for c in /usr/share/OVMF/OVMF_CODE_4M.fd /usr/share/OVMF/OVMF_CODE.fd /usr/share/ovmf/OVMF.fd; do
    [ -f "$c" ] && { OVMF_CODE="$c"; break; }
done
OVMF_VARS_SRC=""
for v in /usr/share/OVMF/OVMF_VARS_4M.fd /usr/share/OVMF/OVMF_VARS.fd; do
    [ -f "$v" ] && { OVMF_VARS_SRC="$v"; break; }
done
[ -n "${OVMF_CODE}" ] && [ -n "${OVMF_VARS_SRC}" ] || { echo "[sandbox] FAIL: OVMF not found"; exit 1; }
cp "${OVMF_VARS_SRC}" ovmf_vars_sandbox.fd

echo "[sandbox] starting QEMU"
qemu-system-x86_64 \
    ${ACCEL} -machine q35 -m 2048 -smp ${SMP} -nographic \
    -drive if=pflash,format=raw,unit=0,readonly=on,file="${OVMF_CODE}" \
    -drive if=pflash,format=raw,unit=1,file=ovmf_vars_sandbox.fd \
    -drive file="${IMAGE}",format=qcow2,if=virtio \
    -nic user,model=virtio-net-pci,hostfwd=tcp::${PORT}-:${PORT} \
    > sandbox-console.log 2>&1 &
QPID=$!
trap 'kill ${QPID} 2>/dev/null || true' EXIT

echo "[sandbox] waiting for /v1/health (timeout 240s) — proves the sandbox didn't break the runtime"
deadline=$(( $(date +%s) + 240 ))
until curl -fsS "http://localhost:${PORT}/v1/health" >/dev/null 2>&1; do
    if [ "$(date +%s)" -ge "${deadline}" ]; then
        echo "[sandbox] FAIL: /v1/health never came up under the sandbox"; tail -n 120 sandbox-console.log; exit 1
    fi
    sleep 3
done
echo "[sandbox] PASS: /v1/health 200 under the sandbox"

echo "[sandbox] asserting in-guest sandbox self-check marker"
deadline=$(( $(date +%s) + 60 ))
until grep -aq 'sandbox\] SANDBOX GATE OK' sandbox-console.log; do
    if grep -aq 'sandbox\] SANDBOX FAILED' sandbox-console.log; then
        echo "[sandbox] FAIL: self-check reported SANDBOX FAILED"
        grep -aE 'sandbox\]' sandbox-console.log | tail -20; exit 1
    fi
    if [ "$(date +%s)" -ge "${deadline}" ]; then
        echo "[sandbox] FAIL: sandbox self-check marker not seen"
        grep -aE 'sandbox\]' sandbox-console.log | tail -20; exit 1
    fi
    sleep 3
done
echo "[sandbox] PASS: sandbox self-check (seccomp + no-new-privs + namespace positive-block)"
echo "[sandbox] SANDBOX GATE PASSED"
```
